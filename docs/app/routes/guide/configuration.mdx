# Configuration

`getOxlintConfig()` accepts one policy level and three independent selectors:

```ts
type ConfigOptions = {
  level?: "essential" | "recommended" | "strict";
  react?: boolean;
  node?: boolean;
  ai?: boolean;
};
```

All options are fixed selectors for prebuilt artifacts. They do not dynamically assemble a configuration.

## Policy levels

### Essential

Use `essential` as the smallest supported adoption baseline. It contains reviewed correctness, safety, accessibility, and framework invariants with a low expected false-positive rate.

### Recommended

Recommended adds broadly applicable project policy and is the default. Start here for a new TypeScript project unless migration cost requires a smaller first step.

### Strict

Strict adds useful but more opinionated policy with a higher adoption cost. Selecting strict is an explicit team decision, not a side effect of enabling another feature.

The levels are nested:

```text
essential ⊂ recommended ⊂ strict
```

Levels control rule membership only. When a rule exists in several levels, its base severity and options stay identical. Moving up only adds rules.

## Project context

`react: true` adds native React and JSX accessibility ownership. `node: true` adds server-runtime and module-system checks. Both combine with every policy level.

```ts
export default getOxlintConfig({
  level: "recommended",
  react: true,
  node: true,
});
```

## AI is independent

`ai: true` does not select a stricter level. It tightens already-active rules and adds rules explicitly classified as AI-only. See [AI mode](/guide/ai-mode) for the guardrails.

## Defaults

| Option | Default |
| --- | --- |
| `level` | `"recommended"` |
| `react` | `false` |
| `node` | `false` |
| `ai` | `false` |

Unknown keys and invalid values throw before an artifact is loaded.
